## 3. 已批准 Spec Delta

### SD-BR-01：一个批次、一个可恢复查询的任务

新增有限 MVP API，经既有 Core `/api/mvp/v1` 与 BFF `/bff/mvp/v1` 映射，仍由 MVP01 拥有：

| 拟议操作 | 用户目的与约束 |
| --- | --- |
| `mvp.create_batch_read_check` POST `/projects/{projectId}/batches/{batchId}/read-checks` | body 只包含精确 `manifestId`；沿用 Idempotency-Key。服务端解析并固定 manifestHash、全部 entry 身份与受支持读取 profile；返回已提交的任务及 request receipt，不等待所有文件读完 |
| `mvp.list_batch_read_checks` GET 同一路径 | 有界分页，列出该批次任务历史和当前活动任务；返回明确 checkId，不用“最新”充当历史引用 |
| `mvp.get_batch_read_check` GET `/projects/{projectId}/batches/{batchId}/read-checks/{checkId}` | 读回任务状态、固定输入、计数、限制与可执行动作；GET 不创建或续跑任务 |
| `mvp.list_batch_read_check_entries` GET 上一路径的 `/entries` | 以原 manifest ordinal 分页，保留所有条目；支持全部/已取得内容/读取受限/未支持/失败/未检查的固定筛选，cursor 绑定 checkId、resultVersion、筛选和页容量 |

写入需当前 OIDC/BFF/CSRF 和 owner/project/batch 权限，身份、路径、profile、脚本、正文及任意参数均不可由客户端注入。请求与任务同事务保存不可变授权和 receipt。同键同 payload 返回同一个 checkId，不重复排队；同键异 payload 冲突。每项目最多一项活动检查，其他幂等键返回已有活动任务引用和明确冲突，UI 导回该任务；不同项目可以等待实例串行调度。并发保护依赖数据库约束和事务，不依赖前端禁用按钮。

### SD-BR-02：保存可审计元数据，分开运行状态和读取结果

新增任务及逐项结果持久化表，均有 owner/project/batch/checkId 和 RLS。预计新增 V0005 迁移；实施时先核对当前迁移序号，不改已有迁移、manifest 或 SourceRef。任务固定 `manifestId + manifestHash`、reader profile 与代码/预算摘要、原 Request 授权、开始/结束时间、执行代次和原尝试，状态变化保留事件。

任务状态拟为 `QUEUED | RUNNING | COMPLETED | INTERRUPTED | FAILED | UNKNOWN`。COMPLETED 仅表示所有条目已有终态检查结果，允许包含单文件失败/未支持；UI 同时显示各类数量和明确结论，不将 COMPLETED 单独翻译为“全部资料读取成功”。任务级依赖/存储/授权故障停止后续读取；已经提交的逐项结果保留，其余显示“未检查”。活动任务尚未检查的条目显示“等待检查”，不提前归为失败。

每项结果绑定原 entryId/ordinal、原接收状态与全部 reasonCodes、完整 SourceRef（如存在）、profile、检查时间、本次读取状态和 limitations。成功取得结构化内容后保存其 canonical 摘要与有限计数（如段落、表格、批注、文本修订数量），不保存原始 stdout/stderr 或任意异常文本。可用与有限内容分别呈现；DOCX 仍至少 LIMITED，外部模板、编号、图片、修订等既有边界必须保留。计数不表示相应业务内容已理解。

首版**只持久化检查结果元数据，不新增提取正文存储**。解析内容计算摘要和计数后释放，单文件完整内容继续使用已批准的按需预览。报告入口写明“查看当前提取内容”；它不能冒充当时已保存的正文快照。未来正式分析必须独立固定输入、执行读取并接纳其证据，不能直接以本报告或其摘要替代正式读取证据。此取舍控制当前存储与恢复范围，也不预建未来分析协议。

全部 manifest 条目都在结果中：非 ACCEPTED 条目不交给读取器，结果为“未进入读取”，显示原接收限制；系统附属文件可明确标注为非业务文档，但仍计入原清单总数。恒等关系为“已终态检查 + 尚未检查 = 原 manifest 全部条目”，分类不能丢行或重复计数。零 ACCEPTED 的批次可生成真实限制汇总，不能显示有内容可供分析。汇总从同一已提交逐项集合派生；轮询不观察一行结果与对应进度不一致的中间事务。

任务有单调递增 `resultVersion`；逐项结果提交及影响分类/计数的状态变化，在同一事务内递增版本。首次/显式刷新筛选列表时，服务端在同一一致性快照中返回版本、该筛选的数量及当前页，后续页和总数均绑定该版本。后台提交使版本变化后，旧 cursor/旧版本请求返回 `409 READ_CHECK_RESULTS_CHANGED`，不返回另一版本的行。UI 保留筛选和容量，明确提示“检查结果已更新，已回到第一页”后重新取得当前版本；终态或版本未变时正常保持分页。首版不维护可分页的历史进度快照；不可变的已完成报告和不同 checkId 的历史仍分别保留。

### SD-BR-03：有界后台执行与明确恢复

提交后由本实例后台调度，每次只读取一份已验证源文件；HTTP 断开、页面离开或会话 Cookie 过期不等于撤销已提交任务。worker 固定原授权 owner/epoch，每份开始及提交结果前复核当前 binding；停用/epoch 变化即停止，不能用重登后的当前权限自动替换旧任务授权。读取业务 GET 每次仍按当前权限，失权页面清除数据。

复用现有固定读取器及所有单份预算，批处理与交互预览共享实际解析槽，不另开一套并发 Python。调度在文件之间让出槽位，交互预览可在空闲边界进入；占用中的预览保持既有“忙碌、可重试”提示。后台等待槽位时不把 BUSY 记为文件解析失败，也不无限重试；首版任务从获得实例执行权起最多运行 60 分钟（含等待、解析及提交），达到时终止本次解析并以明确任务限制结束，其余条目保留未检查。排队等待与已运行时间分开显示。报告元数据每项最多 16 KiB，只含闭集原因、标识、摘要和计数；总规模受已封存清单条目上限约束，API 使用有界分页，不能一次把全部正文或报告载入响应。

启动顺序为已提交 QUEUED → 取得实例/任务独占锁 → 在数据库固定运行代次与 process incarnation → 逐份读取/提交。每次提交使用代次和原授权条件更新；失锁/失权/旧代次的迟到 worker 无权写入结果。复用稳定 inode 的内核 flock，不能只凭超时、PID 或 socket 探测就宣称旧执行结束；读取子进程随父进程停止并清理其独立临时目录。服务关闭需停止调度并终止当前读取，不能重启后与旧读取子进程并行访问同一执行目录。

重启后：已提交而未启动的 QUEUED 任务只有原授权仍有效才可启动；启动核对同时扫描原 RUNNING 和 UNKNOWN 任务，不能只处理第一次中断。先确认旧执行所有者及其读取子进程已结束并取得同一稳定独占锁，再核对不明的逐项提交和原代次；已提交结果按原 entryId/代次/摘要读回，不重写或猜测成功。若已有可证实终态则保留/收敛为该终态，否则推进 fencing 后记录 INTERRUPTED，保留已提交结果并释放项目活动占用。不能确认结束或提交事实则保持 UNKNOWN、保留活动占用，拒绝第二个检查；以后依赖恢复并再次受控启动时，仍会核对该 UNKNOWN，而不是永久略过。

首版不自动续跑中断任务、不覆盖失败结果；用户通过“重新检查整批”创建新 request/checkId，重新处理同一固定 manifest，旧报告可查看。运维使用现有实例的受控停启流程完成后续核对，确认服务/worker 状态与子进程结束的具体步骤及证据须随实现补入现有 runbook；仅发现 PID 不存在或锁已释放不足以证明整个旧进程树已结束。不提供前端“强制成功”、删除旧记录或无依据解除占用按钮。

单份格式不支持、内容为空、资源超限或解析失败留下对应文件结果并继续其他条目；依赖缺失/代码摘要漂移、原件完整性错误、数据库不可用、授权变化或任务总时限停止整项任务，避免把共同依赖故障误报成大量文件损坏。数据库提交不明时先读回原 checkId/entryId 和代次；不能确认则 UNKNOWN，不重新解析来掩盖第一次提交是否成功。所有重试与查询保留原件、历史接收说明和已提交结果。

### SD-BR-04：接入现有批次页面

在当前批次概览添加“检查整批资料”；运行中显示进度与“返回检查结果”，用户仍可使用清单与下载。检查报告作为同一批次内的视图，包含固定批次、检查时间、已完成/总条目数、已取得内容/受限/未支持/失败/未检查分类及过滤入口；使用现有经典分页和蓝白样式，不增加固定高度容器或要求跳往旧操作页。

“仅看问题”对应需要核对的读取受限、未支持、失败及未检查项；系统附属文件仍可在全部清单找到，并与业务文档问题分开说明。报告跳转按需预览或原件下载后返回同一 checkId、筛选、容量和观察版本；版本未变时保留页码，版本已变化时按 SD-BR-02 提示并回到该筛选第一页。刷新/重登从服务端恢复同一报告；切换批次/报告时取消旧查询，迟到响应不得覆盖当前视图。轮询有界，页面隐藏/离开停止查询，服务端任务继续；后台进度更新不静默混入当前筛选页或频繁抢走用户位置，可提示有新结果，刷新/翻页时再按版本规则处理。不将正文或报告存入浏览器持久缓存，响应 no-store。

当前 `analysis:UNAVAILABLE` 保持真实。页面说明检查只验证受支持内容能否提取，下一业务能力是正式分析与澄清；不增加空壳“开始分析”按钮，不形成候选、范围确认或人工批准记录。
