# MVP 已接收资料的只读内容核对

日期：2026-11-04

## 1. 用户结果与分类

用户要求继续下一项 MVP 工作。下一项交付一个可用入口：在真实 `/custody` 项目的文件清单中打开已接收文件，查看有来源的提取内容、表格、批注与修订及其限制，必要时下载原件核对，返回原批次继续查看其他文件。

这是 [M2-1 全包接收与读取](../mvp/mvp-v1-release.md#m2--真实质量手册闭环) 中的内容核对增量，不关闭全包读取验收，也不把逐份预览变成启动分析的必经人工审批。后续分析仍须固定完整输入集合并逐项记录读取结果。首版不新增分析任务、LLM 调用、候选、意见或业务完成状态。

分类为 **T2**：新增 Core/BFF 正文读取契约，并使未可信的 Office 内容进入一个新的解析与展示路径，需要明确权限、资源和版本边界。用户于 2026-11-04 回复“批准”，批准绑定独立审查通过的设计 SHA-256 `dae4e59ac7f46f8d6f7617fa1bd2cb0565e174d6958e5a222f18183acc5c0211`；授权本地实施与验证，Git 交付、测试实例升级和外部 Runner 修改各按已有授权范围处理。本设计不请求修改外部 Runner。

## 2. 依据与首版限制

- 测试实例已运行 `mvp.zip-input@4` / V0004。2026-11-04 只读查询确认客户新批次已有真实接收结果：192 个条目，90 个 ACCEPTED（54 DOCX、36 Markdown），101 个系统附属条目、1 个活动内容受限条目。48 份 DOCX 带 `EXTERNAL_TEMPLATE_NOT_LOADED`。这证明实际新批次接收，不证明业务文档清单完整、内容已读或人工验收通过。客户路径、正文与详细清单不写入本设计。
- 设计前的 [MVP01](../module-specs/Module-Spec-MVP01-DocumentDelivery.md) 只提供封存清单与受控原件下载；不能直接用原 ZIP 绕过受限条目，也不能把 ACCEPTED 当成 READ。
- 正式 Runner 的 `runner_evidence/reader.py` 已有固定读取能力。只读核对基线为 `434569400e6c5882697652774ff3128a66ff4635`，工作区干净。读取器支持 Transitional DOCX 与 UTF-8 文本，提取段落、编号定义、表格及合并标记、页眉页脚、批注、修订和域等；不解释图片。XLSX 与 Strict DOCX 尚不能由该读取器提供正文。
- 合成反例确认：表格内文字也包含在段落序列中，表格另列；输出没有原始段落/表格块顺序关系，编号定义不是完整可见编号，且不是 Word 排版。首版明确称为“提取内容”，不伪装为忠实全文预览，不新写第二套 DOCX 解析器填平这些差异。

## 3. 已批准 Spec Delta

### SD-SP-01：只读入口与固定身份

新增 `mvp.get_source_preview`：Core GET `/api/mvp/v1/projects/{projectId}/batches/{batchId}/sources/{sourceId}/preview?manifestId={manifestId}`，BFF 使用既有 `/bff/mvp/v1` 对应映射。只接收这些身份字段；不接收路径、URL、脚本、模型参数或客户端正文。GET 仅计算可丢弃的读取结果，不写业务事实；页面只在用户明确打开文件后调用，不预取整批。

复用现有 OIDC、BFF binding 与逐请求当前授权检查。服务端核对 owner/project/batch/已封存 manifest/entry 的完整归属，且 source 必须是该 entry 的 `ACCEPTED_ENTRY`；`ORIGINAL_ZIP`、无 SourceRef 条目、不匹配 manifest、跨项目/用户请求均不进入读取器。按照受控 store 的完整 SourceRef 核对 bytes/hash/length 后，仅将验证过的字节副本交给读取器。返回结果前再次检查当前授权；失权后丢弃结果。保持原下载接口不变。

响应为闭对象，包含 `sourceRef, manifestId, profileId, status, limitations, sections?`。`status` 只表达本次预览：`AVAILABLE | LIMITED | UNSUPPORTED | UNAVAILABLE`，不复用业务 READ。字段形状、限制原因闭集与错误映射在批准后的 owning API/Spec/Test 中同步冻结，不允许把 Runner 原始 JSON 任意透传给浏览器。身份/权限/存储完整性错误继续使用既有错误通道；读取依赖不可用、解析失败或超限为明确可恢复的预览失败。

### SD-SP-02：复用固定读取器，独立标注覆盖

采用版本化 `mvp.source-preview@1`。Core 适配器只读获取固定 Runner 读取代码，将已校验代码快照与单份已校验文档副本放入隔离临时目录，调用现有 `collect`，再校验来源绑定、输出文件类型、摘要和结构并归一化响应。该 collector 的最小输入清单只服务本次技术读取，不注册分析 v0.1 业务协议，不形成未来 revision-round 输入授权。

锁定依赖为 Runner 上述 revision 中以下文件，不能只检查 Git HEAD 而忽略脏文件，也不能校验后从可变目录导入另一份代码：

| 文件 | SHA-256 |
| --- | --- |
| `runner_evidence/__init__.py` | `c7f42bcb90f5988386d9f43c100d5d2ad29b43b42d65a7505d7476db9af81a79` |
| `runner_evidence/common.py` | `e43bb39396aa9044e427f3493cbb69c09f40cf63a2ab27fee51dfd70dace06d1` |
| `runner_evidence/reader.py` | `cdb41d2cfd3f393b6f64d70f541a397248b65604b53b3e1407f74a6a4380168f` |

使用部署配置中的 Python 3.10+ 与固定代码位置，不从请求指定；Python 以隔离模式禁用用户 site、字节码写入和任意环境导入，不把服务凭据传给子进程。缺依赖或摘要漂移时仅使预览不可用，原托管/下载继续工作；不自动安装、不修改 Runner、不回退到 Agent/LLM。读取 profile 包含适配器版本、固定代码摘要和预算；运行证据记录实际 Python 版本。

Markdown 保留完整源码和严格 UTF-8 文本，源码权威来自 Core 已验证原始 bytes 的严格解码，保留 CRLF/CR/LF；不使用 collector 的 `Path.read_text` 或可读 Markdown 输出替代原始源码，因为它会归一化换行。展示复用现有安全 Markdown 渲染。DOCX 分为正文段落、表格、页眉页脚、批注、“已提取的文本修订”及读取说明，显示读取器提供的结构位置，不编造原文行号/页码；不将重复的表格文字解释为原件中另有一份内容。文本修订仅覆盖 `ins/del/moveFrom/moveTo`，按类型分组而非原文顺序，缺少完整原位锚点；`rPrChange/pPrChange` 等格式修订不在首版覆盖内，提取 0 条不能宣称原件无修订。DOCX 一律至少为 LIMITED，说明非原版排版、表格另列、编号、修订和图片等覆盖边界；collector 的 `technicalReadCeiling=READ` 不取消这些限制。无实际内容、失败或未知输出不能伪装成空的成功预览。

XLSX 和 Strict DOCX 显示 UNSUPPORTED 及“可下载原件核对”，不改变既有接收结果。继承 entry 的所有接收说明，尤其外部模板未读取；不获取模板目标，不将模板地址展示给用户。修订、批注、域指令与文件内容都是不可信资料，不执行其中的命令、链接或业务指示。

### SD-SP-03：有界解析与安全展示

不能因为文件曾 ACCEPTED 就跳过本次解析保护。Core 在独立、可终止的读取 worker 中复用现有 ZIP/XML 安全能力，对读取器将访问的全部 XML（含 styles、numbering、comments、页眉页脚等）预检：拒绝 DTD/实体声明，检查真实解压长度、CRC、路径、重复项、根与 namespace，限制深度和节点；不得只检查主文档。未支持结构作为本次预览限制/失败，不能回写历史条目。

首版单份预览预算固定为：源 bytes 不超过既有 50 MiB 接收上限；Office 部件不超过 1000；实际总解压不超过 64 MiB、单 XML 不超过 16 MiB、XML 深度不超过 128、累计元素不超过 200000；归一化响应 UTF-8 不超过 8 MiB；从请求开始计算总时限 30 秒。另保留既有路径、压缩比例及 512 MiB 保守内存计量，在构造大型 XML 树和输出前预检。计量不能只依赖压缩包声明或读取器返回后再检查。

调用 Python 前，按固定 reader 的输出路径计算保守放大预算：段落与表格内文字重复、嵌套段落/修订的祖先重复、每段重复的编号定义、批注定位数组与链接关系的跨部件重复、JSON 转义及 Markdown 字符串均计入；首版不支持嵌套表格，无法证明上界的形态直接返回有说明的预览限制。只检查 XML 大小或元素数量不足以放行。对 Python 对象、解码缓冲及重复字符串保守估算后不得超过上述内存预算，需用针对放大路径的合成反例证明调用前拦截。

执行期另设保护：结构化 JSON、可读 Markdown 每个原始产物最多 8 MiB，索引最多 256 KiB；stdout、stderr 各最多 64 KiB；单次临时目录总量（含输入副本、固定代码与所有输出）最多 80 MiB。使用文件大小资源限制与输出流计量，达到限制即终止，不等归一化响应生成后再检查。父进程还在执行期监测 worker/读取子进程内存，达到 512 MiB 即终止并清理；若部署环境不支持硬 RSS 限额，必须明确这是“调用前保守上界 + 执行期保护”，不能宣称无瞬时超调的 OS 硬内存隔离。上界检查或执行期保护不可用时，预览失败关闭；不能改成无限额运行。资源限制机制和反例必须在目标 macOS 环境验证后才能交付。

每个 Core 进程最多一个活跃读取任务，额外请求返回可重试的忙碌提示，不建立持久队列。请求取消、超时或失败终止本次 worker/子进程并清理临时副本；服务重启清理本实例遗留临时目录，不触及原件或其他实例。API 主进程不执行同步 Office 解析；上述资源边界必须在支持的 macOS 测试环境有实际反例验证，不能用进程退出后观测内存代替执行期约束。

固定读取工具不是 Agent 沙箱。此范围只允许审查过的无网络固定代码访问所提供的副本；禁止外部资源解析、Office 应用启动、shell 拼接和动态插件。XML/URL 外部访问反例需证明没有文件目标或网络访问。浏览器复用安全 Markdown/表格组件，禁止原始 HTML、事件属性、脚本/iframe、远端图片自动加载；DOCX 字符串按文本显示，结构化表格保留合法合并关系。输出还需限制嵌套、数组及字符串规模；不可信的 gridSpan/vMerge 先与有界的实际行列网格核对，不按原始跨度值分配数组或直接设置 DOM 跨度。服务端输出校验和前端安全渲染不能互相替代。

### SD-SP-04：页面与历史边界

清单中 ACCEPTED 文件有“查看内容”；受限、损坏、系统附属条目继续展示接收原因。内容打开后占用主内容区域，显示文件名、所属批次、接收说明、提取限制和“下载原件/返回文件列表”；使用蓝色、白底、页面自然滚动。窄屏纵向排列，宽表在自身区域横向滚动，页面不横向溢出。

保留原批次及分页返回位置。切换文件、退出或失权时取消请求并清理旧正文；迟到响应不能覆盖当前文件。刷新/重登通过同一批次与来源重新读取，无须重传；不将正文写入 localStorage/sessionStorage 或通用日志，不使用共享缓存，响应 `Cache-Control: no-store`。失败可显式重试同一来源，重试无业务写入与外部模型副作用。

不新增数据库表/迁移，不修改 manifest、SourceRef、batch 状态、历史接收 policy、原件或模板；预览结果不作为后续分析的持久读取证明。后续若需保存全包阅读结果、版本化分析输入或真实 Runner 任务，应在相应业务增量中确定，不能从本次浏览行为推导。

## 4. 影响范围与执行

本地实现已同步 MVP01 Spec/Test、[Core contracts](../high-level-docs/03-core-contracts.md) 及 UI01 Spec/Test 的相应条目，并实现 `modules/document-delivery` 的受控读取适配器、API/BFF 路由及 custody 页面。独立 Runner 仓库只读，不重构旧七模块，不扩展 XLSX 读取，不恢复嵌套压缩功能。一次交付入口、读取、限制及恢复，避免分成不可用的前后端任务。

设计阶段配置化 `docs` 与独立设计审查。实现需要 `vibe verify full --json`：本次含 Core、安全和跨层契约，先前纯 UI 的数据库测试豁免不适用。运行在隔离构建目录，避免清理现有测试实例所用产物。先用合成反例核对身份、读取和资源边界，再用用户现有 sealed 来源做只读逐份核对；客户内容/截图只留受控本地证据，不复制到公开测试或 Git。指定测试实例现已按用户批准升级至 `mvp.source-preview@1`；原数据库迁移版本仍为 V0004，原托管事实与原件保持不变。正式登录、预览、刷新重登、下载及 90 份已接收来源的只读接口覆盖已核对；人工内容验收仍待用户完成。
