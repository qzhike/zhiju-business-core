# Zhiju Business Core 当前路线

更新：2026-11-05。推进方向从本文件进入；里程碑、checklist 与证据定位统一维护在 [mvp-v1-release](../mvp/mvp-v1-release.md)，不在此重复任务状态。

## Current — 收尾 UI 验收，推进真实资料内容核对

复用现有页面与模拟旅程，按更新后的 PRD 订正为“质量手册 → 控制程序 → 管理制度及记录表单”，连通首页、项目、审阅、反馈、恢复和模拟包下载。完成 release 计划的 **M1**，由用户完整试走并确认。

按用户继续下一项的要求，利用已经运行的真实托管入口推进 **M2-1 接收核对与兼容性**：先解决实际文件接收误判与可解释限制，再接通全文读取及分析。[已批准的接收兼容性增量](../decisions/mvp-document-intake-compatibility.md)已完成验证、独立复审及获准的指定测试实例升级，实例运行接收策略 @4 / schema V0005；已只读确认客户新批次实际接收 90 份 DOCX/Markdown，接收限制仍保留。当前增量为[已接收资料只读内容核对](../decisions/mvp-source-content-preview.md)，让用户从真实清单查看提取内容与限制；入口、固定读取器适配与安全展示已实现，并经完整验证、独立复审和用户批准升级指定测试实例；上线接口已核对 90 份来源，人工内容验收尚未完成。逐份预览不替代全包阅读结果或人工内容验收。此工作不宣称 M1 全项完成，也不直接启动未设计的 Runner 执行链。

已有 U1–U3 历史验收不代表本次新流程已通过；B1 托管候选保留，不继续按未确认的旧 B2 文档扩展后端。

单文件查看及经典分页已在指定测试站完成验证和发布。[整批资料读取检查与结果汇总](../decisions/mvp-batch-read-check.md)已完成 T2 设计批准、实现、full 与独立审查，并于 2026-11-05 按用户授权升级指定测试实例：一次检查封存批次，保存逐项技术读取结果、限制和进度，刷新或重登后可读回。合成资料的上线流程已核对；同日已复核真实第 8 批的完成报告、全部来源与原件，以及关键内容展示。用户已确认质量手册以该批次已核对的 Markdown 来源为准；当前须确认记录表单输入范围和已说明的读取限制，再收尾人工内容验收，M2-1 保持未关闭。检查汇总仍是技术读取结果，正式分析尚未接通，也不增加逐份预览审批。

## Next — 逐段接通真实业务，再做完整输入验收

M1 通过后，按 **M2 真实质量手册 → M3 完整业务与 Markdown 包 → M4 bopu 全量验收及发布准备**推进。后端每次围绕一个可观察的用户结果补齐；先复用，再以实际阻塞决定局部替换，不预设整体重写。

本版完成以用户重新整理并确认的 bopu 完整输入为基线。按 2026-11-03 最新决定，上传 ZIP 不允许包含嵌套压缩文件，发现后整包拒绝并要求用户整理重传，不开发嵌套 RAR 解包能力。小样本与 mock 不能代替全量验收；不另设“300+ 份”数量门槛。产品细则见 [可用闭环](../mvp/usable-loop.md)，技术与验证规则按 [HL-Spec](../high-level-docs/HL-Spec.md)和 owning Spec/Test 执行。

## Later — 依据实际使用决定

更大规模与效率优化、更多输入类型、Word/Excel 输出、其他 Harness、外部渠道及多租户均不抢占本版闭环。是否纳入后续版本由真实使用结果决定。
