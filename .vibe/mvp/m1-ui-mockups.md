## 图 1：导航与业务顺序

项目内保留四个主入口。“处理结果”只有总览和文件详情两级；整体分析属于准备工作，三个业务阶段负责修订和定稿。

        |
        +-- 项目概览
        |
        +-- 资料
        |     +-- 上传批次 / 原包 / 目录 / 原始文件
        |
        +-- 处理结果
        |     |
        |     +-- 总览

范围确认、执行恢复、阶段确认从当前任务进入，用局部面板或对话框承载，不再并列堆进项目主导航。工作台首页沿用已初步验收的方向，本稿集中约束项目内页面。

- 图中的“失败”是已知结束的失败。状态未知时，主要动作必须换成“核对执行状态”，不能提供直接重跑。

## 图 5：文件详情与意见

首次打开默认“累计变化”：左侧原始文件、右侧所选轮次修订稿；用户可切换“本轮变化”检查这轮反馈带来的修改。

```text
+----------------------------------------------------------------------------+
| < 返回结果总览     控制程序 / R2 / 文件控制程序                             |
| 模拟演练                                                                   |
+----------------------------------------------------------------------------+
| 文件控制程序.docx                                                          |
| 比较 [累计变化 v]    显示 [左右对照 v]    [目录]    [意见与历史]             |
| 当前比较：初始底稿 B0 -> R2 修订稿 v2                [查看来源与精确版本]   |
| [上一处修改] [下一处修改]    修改 2 / 5    [展开未变内容] [正文预览]         |
+-------------------------------------+--------------------------------------+
| 原始文件：提取正文                  | 所选轮次修订稿：v2                   |
| 初始底稿 B0                         | 控制程序 / R2                        |
+-------------------------------------+--------------------------------------+
| 4.2 文件批准                        | 4.2 文件批准                         |
|                                     |                                      |
| - 文件经负责人批准后发布。          | + 文件经授权负责人批准后发布，       |
|                                     | + 并登记发布版本与生效日期。          |
|                                     |                                      |
| 4.3 文件发放                        | 4.3 文件发放                         |
|   文件发放应保留记录。              |   文件发放应保留记录。               |
|                                     |                                      |
|             正文对照持续占据主要阅读区域                                  |
|                                     |                                      |
+-------------------------------------+--------------------------------------+
| 选中修改：4.2 文件批准                                                     |
| 修改理由：[展开依据]    相关问题：[查看]                                    |
|                                                                            |
| 对此修改的意见：                                                           |
| [请说明建议修改的内容__________________________________________________]   |
| [保存意见]                         保存于本次模拟会话；绑定此文件 / R2 / v2 |
+----------------------------------------------------------------------------+
```

图中下方意见面板为选择修改或点击“意见与历史”后的展开状态，默认收起。文件目录同样默认收起；不能让目录、两份正文、意见区长期组成四列，也不能在正文上方堆入大段依据说明，把阅读区域挤到页面底部。

| 比较方式 | 左侧 | 右侧 |
|---|---|---|
| 累计变化，默认 | 该文件初始底稿 | 所选轮次对应的精确候选版本 |
| 本轮变化 | 上一轮对应的精确稿件 | 所选轮次对应的精确稿件；沿用时可以是同一版本 |

第一轮的“本轮变化”使用本轮实际输入底稿，并明确标注。DOCX 原件显示可追溯的提取正文，不承诺还原 Word 排版；来源定位和读取限制可展开查看。两端版本必须可追溯，不能把旧规范化文本索引冒充原始文件物理行号。

- 文件详情保存针对当前文件、轮次和版本的意见；在结果总览汇总后提交下一轮修改。
- 项目或阶段意见从总览的“讨论与意见”进入，不能误绑定到当前打开的文件。
- 新结果到达时只提示“有新轮次可查看”，由用户主动切换。
- 返回总览恢复原轮次、筛选、选择及滚动位置；草稿不串到其他文件。
- 保存意见、查看差异和生成候选，都不等于阶段定稿。

文件详情必须覆盖以下状态：

| 文件状态 | 详情页面必须显示 |
|---|---|
| 尚在分析或计划阶段 | 原文、分析发现、拟议动作；修订区说明“尚未生成候选” |
| 已确认新增，无客户原件 | 左侧“无原件，已确认新增”，右侧显示实际候选 |
| 本轮沿用 | 明确“沿用 v1，本轮无变化”，仍可阅读全文，不制造新版本 |
| 本轮生成失败 | 修订区显示失败原因；上一版只能通过明确入口查看，不能冒充本轮产物 |
| 本轮范围内应有结果但未返回 | 保留文件行，显示“本轮未返回结果”，不能静默消失 |
| 原件无法读取 | 显示读取限制及补充入口，不伪造原文 |
| 预期待补项 | 显示适用性、来源和待确认事项，不直接断言“客户没有该文件” |
| 未纳入所选轮次 | 说明未纳入原因；可查原件或历史版本，不标成该轮已处理 |

## 实施与验收边界

- 在既有 Workspace Web 中落实本稿，保持同一项目的导航、版本、草稿、请求与历史；不建立第二套原型应用。
- 技术诊断与场景控制可展开，模拟身份与内存/刷新限制持续可见；主要流程使用业务语言。
- 当前项目最多一个活动修改批次；UNKNOWN 核对原请求、部分失败保留成功文件、旧结果不覆盖当前阅读/草稿/定稿等既有约束继续适用。
- UI-MVP-M1-010 采用新的上下布局验收；UI-MVP-M1-011–016 覆盖本稿新增页面与状态要求。旧布局和旧版 CI 不能证明新要求通过。
- 用户批准本稿只确认设计。修改后的页面仍需独立审查、适用的配置化验证、M1-3 完整试走及当前 Runner 脱敏输出展示核对。
